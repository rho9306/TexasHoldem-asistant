## 1. 项目概述

德州扑克长期收益辅助与策略训练工具：玩家输入手牌、公共牌、位置、翻前场景、对手档案、底池与筹码信息，软件通过**范围化蒙特卡洛模拟**计算胜率、EV、底池赔率，结合**GTO图表**与**策略启发式引擎**给出行动建议与下注尺寸，通过**桌子动态适配器**根据全桌风格调整打法倾向，并追踪长期收益、支持赛后复盘。

**核心价值：** 纯数学+GTO驱动、离线可用、输入即得结果、帮助玩家学习德扑数学与策略思维、历史数据反哺决策。

## 3. 技术架构

### 3.1 技术栈与分层

```
前端：    Vite + 原生 JavaScript + CSS（无框架）
核心算法：poker_assist/core/*.cpp（C++17）→ Emscripten 编译 WASM
数据：    localStorage（sessions/hands/opponents/settings）+ JSON导出导入
PWA：    Web App Manifest + Service Worker（离线可用）
部署：    GitHub Pages / Cloudflare Pages（¥0）
```

**四层架构（v4.0 新增策略层）：**

```
┌─ UI 层（原生JS）
│    选牌器 / 位置条 / 对手档案卡 / 仪表盘 / GTO图 / 历史 / 复盘
├─ 策略层（原生JS）★ v4.0 新增
│    GTO图表查询 · 牌面纹理分析 · 下注尺寸规则 · MDF/α · outs/4-2法则
│    隐含赔率 · 范围映射（类型→169掩码）· SPR · Nash推弃 · 桌子动态适配
│    原则：只做查表与简单公式（无重计算），便于修改与单测
├─ 引擎层（C++ → WASM）
│    范围化蒙特卡洛采样 · 牌力评估 · EV计算 · 范围透视统计
└─ 数据层（JS）
     localStorage 四存储键 + 导出导入 + 上限FIFO
```

**分工原则：** 数学运算在 WASM（快），策略规则在 JS（好改好测）。

### 3.3 WASM 接口设计

```javascript
// 范围化胜率计算（核心新接口）
calculateEquityV2(
  heroHand,                    // ["As","Kh"]
  board,                       // []~5张
  opponents: [ {mask: Uint8Array(169)} ],  // 每对手一个范围权重掩码（0-100）
  iterations                   // 500/2000/5000
) → {
  winRate, tieRate, lossRate,
  rangeStats: {                // ★ 对手范围透视（辅助件⑥，模拟中顺带统计）
    totalCombos,               // 对手范围内总组合数（扣除已知牌占用）
    beatPct, tiePct, losePct,  // 模拟中领先/平/落后占比
    dangerHands                // 胜率最低的3个手牌类
  }
}

// 决策与EV（沿用，策略风格参数化）
evaluateDecision(winRate, pot, call, raise, adviceStyle)
  → { evCall, evRaise, potOdds, requiredEquity, advice, adviceLevel }
```

**范围采样算法（C++）：**
```
每手开始：按169格权重预计算累积权重表（O(169)，仅一次）
每次迭代，对每个对手：
  1. 按累积权重随机选手牌类（O(log169)）
  2. 从该类未被占用（hero/board/其他对手已用）的具体组合随机取一
     （对子6组合、同花4、异花12）
  3. 若该类组合全被占用 → 按权重重采样
  4. 补全公共牌（其余随机）→ 评估比牌 → 记录胜负与范围统计
全100%掩码 ≡ 原纯随机行为（向后兼容，旧随机模式即特例）
```

```

    ↓

```

## 5. 核心算法与策略引擎

### 5.1 范围化蒙特卡洛（引擎层）

见 §3.3 采样算法。范围数据模型：

```
13×13手牌矩阵 = 169个手牌类
  对角线13格 = 口袋对（各6组合）
  上三角78格 = 同花牌型（各4组合）
  下三角78格 = 异花牌型（各12组合）     合计 1326 种起手组合
每格权重 0-100 = 纳入概率；范围 ≈ 169字节 Uint8Array
```

### 5.2 对手范围从哪来（策略层 ranges.js）

1. **GTO基准表**：位置开牌表（UTG窄→BTN宽）为骨架
2. **类型修正系数**（实现期用公开基准数据校准）：`紧凶≈0.8× / 紧弱≈0.6× / 松凶≈1.3× / 松弱≈1.5×` 基准表宽度
3. **滑条连续映射**：looseness 0-100 → 目标VPIP 10%-60%，从强到弱排序截取手牌类
4. **观察值优先**：对手 VPIP 观察值（≥20手）优先于类型默认值
5. 面对加注的防守场景：相应收窄（保留强牌段）

### 5.3 GTO 图表系统（charts.js）

- **内嵌约16张表**（每表169字节，合计<10KB）：开牌表5张（UTG/MP/CO/BTN/SB @100BB）+ 防守表约8张（BB/SB vs 常见开牌位的高频场景）+ **Nash推弃表3档**（≤7BB/8-10BB/11-15BB）
- 数据为**公开的求解器共识简化范围**（手工整理，无商业产品数据，合规）
- 联动：计算页场景 → GTO页自动定位；短码（有效筹码≤15BB）自动切 Nash 推/弃模式
- GTO 展示不受"建议风格"设置影响（基准答案就是基准）

### 5.4 策略引擎 v2 规则（sizing.js / texture.js / mdf.js）

**A. 牌面纹理分析**：同花性（彩虹/双同花/单调）+ 连线性（连子/半连子/干燥）+ 结构（对子/高牌面）→ 综合评级 干燥/中性/湿润

**B. 下注尺寸建议**：
- 进攻者（翻前加注者）：干燥面 c-bet **33%** 高频率；湿润面 **66-75%** 低频率（价值+半诈唬）
- 防守者：面对小注放宽跟注；面对超池仅强牌继续
- 价值/诈唬平衡（河牌）：1/3池≈3:1、2/3池≈2:1、超池≈1:1
- 价值下注原则（"大牌赶走小牌"的系统化）：顶对以上主动下注保护，听牌要么付代价要么弃权

**C. 公式组**（mdf.js / implied.js，纯公式）：
```
MDF = 1 − bet/(pot+bet)        α(诈唬保本成功率) = bet/(pot+bet)
  33%池→α25%/MDF75%   75%池→α43%/MDF57%   150%池→α60%/MDF40%
outs概率：翻牌→河牌 ≈ outs×4%；单街 ≈ outs×2%（4-2法则）
  同花听9·两头顺8·卡顺4·口袋对追套装2·后门听1-2（自动检测）
隐含赔率：需胜率 = call/(pot+call+future)，future 按对手类型默认
  （松弱跟注站=高隐含赔率敢跟；紧凶=打折慎跟）
SPR = 有效筹码/底池；SPR≤4且顶对以上→倾向打光；SPR>8且弱顶对→控池
```

**D. 决策横幅优先级**：① 短码→Nash推/弃 ② 翻前→GTO行动+胜率对照 ③ 翻后→胜率/EV主建议+策略标签

### 5.5 六个辅助判断件（汇总）

| # | 名称 | 实现 | 位置 |
|---|------|------|------|
| ① | outs计数+4-2法则 | 规则检测听牌 | 计算页策略卡 |
| ② | MDF/α速查 | 查表 | 防守时策略卡 |
| ③ | 起手牌百分位 | 169行静态表 | 选牌后即时显示 |
| ④ | EV双曲线 | 历史数据累计求和 | 历史页 |
| ⑤ | 隐含赔率 | 公式+对手类型默认 | 听牌时策略卡 |
| ⑥ | 对手范围透视 | 模拟顺带统计（rangeStats） | 计算页策略卡 |

### 5.6 桌子动态适配器（tableDynamics.js）

```
桌均VPIP = mean(各对手 max(类型默认VPIP, 观察VPIP≥20手时))
桌均凶度 = mean(各对手凶度滑条值)

四象限画像与打法修正：
  松弱桌(VPIP>35%,凶度低) → 紧凶化：诈唬类建议×0.6，薄价值放宽，大注榨取
  紧弱桌(VPIP<25%,凶度低) → 松凶化：偷盲/诈唬×1.4，对手弃牌率上调
  紧凶桌(VPIP<25%,凶度高) → 尊重反击：3bet频率上调，防守收窄
  松凶桌(VPIP>35%,凶度高) → 控池防守：对抗加注跟注标准收紧
  均衡/对手<2人/样本不足  → 无修正，按标准GTO
```

- 修正作用于**策略层建议倾向**；胜率数学不变；Nash表不变
- 与「建议风格」设置叠加：桌子适配=场景层，风格=个人偏好层（决定缓冲）
- 设置开关「自动桌子适配」默认开；关闭只显示画像不修正
- 复盘统计可按"当时桌子画像"分组
- 样本保护：对手观察<20手用类型默认值

### 5.7 已知局限（关于页如实展示）

- 对手范围为简化建模（类型系数+滑条），非精确读牌；位置/筹码深度简化处理
- 加注EV为简化模型（对手 50%跟注/30%弃牌/20%再加注假设）
- GTO图表为公开共识简化版，非深度求解器输出
- 个人弱点统计受样本量限制（<20手不出结论）

## 6. 数据结构（localStorage，v2）

```
texas.sessions    Session[]
texas.hands       HandRecord[]   ← 上限1000手，FIFO，超出提示导出
texas.opponents   OpponentProfile[]
texas.settings    Settings

Session    { id, name, date, venue?, handsCount, netResult, evTotal }

HandRecord {
  id, sessionId, timestamp,
  hand: ["As","Kh"], board: [...], street,        // street: preflop|flop|turn|river
  preflopScenario { heroPosition, raisesBefore, limpers },
  inPosition: bool, heroRole: "aggressor"|"defender",
  opponents: [{ profileId, typeSnapshot, vpipSnapshot }],
  tableProfile,                                    // 四象限|balanced
  pot, call, myStack, oppStack, effectiveStack,
  winRate, tieRate, equity, evCall, evRaise, potOdds, requiredEquity,
  advice, adviceLevel, sizing, gtoAction, texture, strategyTags[],
  action,                                          // 用户实际行动
  result,                                          // 实际盈亏（手输）
  followedAdvice, deviationType?, tags[], notes
}

OpponentProfile {
  id, name,                                        // 如"2号位"
  type: "TAG"|"LAG"|"tight-passive"|"loose-passive",
  looseness: 0-100, aggression: 0-100,             // 滑条连续值
  handsSeen, vpipObs?, pfrObs?, updatedAt
}

Settings { simulations: 500|2000|5000, adviceStyle, autoTableAdaptation: true, theme }
```

**数据依据闭环：** 添加对手→优先推荐历史档案；实测VPIP与标签矛盾→提示一键采用建议值；弱点场景→计算页轻提示。

## 7. 会话与复盘系统

- **Session**：计算页顶部指示+"开始新会话"；历史页按会话分组
- **对手档案持久化**：跨手跨会话留存，下次直接选用；每手自动记入池观察（场景推断+一键修正）滚动算 VPIP
- **复盘视图**：单手复盘卡（牌面重绘/建议对照/偏离标记/笔记）、智能筛选（偏离手/亏损手/按场景）、弱点矩阵（样本<20手不出结论）
- **存储与备份**：localStorage≈5MB（一手<1KB，可存数千手）；上限1000手FIFO+提示导出；**导出/导入JSON全量备份**（含格式版本校验，换设备迁移）

## 8. 错误处理

| 场景 | 处理 |
|------|------|
| 重复选牌 | 已用牌置灰禁点+行内提示 |
| 手牌未满看结果 | 引导文案，不计算 |
| 底池/筹码输入非法 | 红框+提示，EV区 `--` |
| 筹码≤0 或 跟注>有效筹码 | 提示修正；SPR/全下注逻辑按短码处理 |
| 翻牌前（无公共牌） | 正常计算（随机5张），阶段标签"翻前" |
| 对手档案被删但历史引用 | 复盘卡显示"已删除对手"占位 |
| 对手观察<20手 | 用类型默认值（不提示为错误） |
| localStorage 满/不可用 | 降级仅内存+设置页提示导出 |
| 导入JSON损坏/版本不兼容 | 校验失败提示，不写入现有数据 |
| WASM 加载失败 | "加载计算引擎失败，请刷新"错误页 |
